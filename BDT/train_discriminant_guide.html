pNN/run3_scouting/BDT/train_discriminant.py

Training the discriminant with train_discriminant.py

Trains a signal-vs-background discriminant for the scouting DQCD analysis, with one independent model per lxy bin. It can be an XGBoost BDT or a parametric neural network (PNN) in PyTorch, both using the same data, weights and train/test split.

What it does

  • Signal: private DQCD tuples of the chosen scenario (/ceph/cms/store/group/Run3Scouting/<sig-dir>), one file per point (mπ, mA, cτ).
  • Background: MinBias filtered with DoubleMuOS43, 2024 (tuples_minbias), weighted by cross section (≈ 5.18·105 pb after the filter).
  • Inputs: 138 per-event variables (SV1 and SV2 plus their two muons each), the same list as workingpoint.py. With --conditional, the signal parameters are appended at the end.
  • lxy bins (SV1, cm): [0, 0.2], [0.2, 3.1], [3.1, 11], [11, 70]. One model per bin.
  • Split: 70/30 by event number (evtn % 10 < 7 → train). Test events are never used for training.

Requirements

  • Read access to /ceph/cms/store/group/Run3Scouting.
  • Python 3 with numpy, pandas, uproot, xgboost, scikit-learn, matplotlib and mplhep.
  • For --model pnn, also torch. Without it the script exits with a clear message.
  • Memory: loading the data takes 10–15 minutes, and training is capped at 15 M events by default (--train-max-events) to bound RAM usage.
Note: torch is not installed in the current environment (ModuleNotFoundError). The BDTs work; for the PNN, activate an environment with PyTorch, ideally on a GPU node.

Check the environment:

python3 -c "import uproot, xgboost, mplhep, sklearn; print('BDT ok')"
python3 -c "import torch; print('torch', torch.__version__, 'cuda:', torch.cuda.is_available())"

ROOT reading uses 4 decompression threads. Change it with the WP_READ_THREADS environment variable (1 disables the pool):

export WP_READ_THREADS=8

How to run it

The examples are run from pNN/run3_scouting/. Output is always written next to the script (inside BDT/), so the working directory does not change where files end up.

BDT (equivalent to workingpoint.py)

python3 BDT/train_discriminant.py --model bdt --scenario A

Non-parametric neural network

# Without --conditional: a plain fully connected classifier
python3 BDT/train_discriminant.py --model pnn

Parametric NN (mA/mπ and cτ as inputs)

python3 BDT/train_discriminant.py --model pnn --conditional --cond-var mratio ctau

Hold signal points out of training (interpolation test)

# All cτ of mpi=4, mA=1.33, and only cτ=10 mm of mpi=2, mA=0.67
python3 BDT/train_discriminant.py --model pnn --conditional --cond-var mratio ctau \
    --holdout 4:1.33 2:0.67:10

Single mass point, L1 required, on GPU

python3 BDT/train_discriminant.py --model pnn --mass-point 4:1.33 --require-l1 --device cuda:0

Tuning the network

python3 BDT/train_discriminant.py --model pnn --conditional --cond-var mratio \
    --pnn-layers 4 --pnn-nodes 128 --pnn-dropout 0.1 --pnn-lr 5e-4 \
    --pnn-batch-size 2048 --pnn-max-epochs 300 --pnn-patience 20 \
    --out-name pnn_tests

In the background with a log

nohup python3 BDT/train_discriminant.py --model pnn --conditional --cond-var mratio ctau \
    > train_pnn_condMratioCtau.log 2>&1 &
tail -f train_pnn_condMratioCtau.log

Code walkthrough

The file is split into numbered sections. This is the order in which main() runs them:

  1. Configuration. parse_args() reads the command line and build_config() collects everything into a Config, including the output directory name. §3 · lines 153–264
  2. Signal inventory. find_signal_files() uses a regex to find tuples_Signal_Scenario<S>_(Par|Priv)_2024_mpi-…_mA-…_ctau-…mm_2024*.root, prefers already merged files (*_2024.root) and applies --mass-point. §4 · lines 270–304
  3. Data loading. build_dataset() reads each ROOT file with read_tuple() in 2 M chunks into a float32 array, computes dxy_lxy (|dxy| divided by lxy·m/pT, not stored in the tuples), assigns the lxy bin with pd.cut and, if conditional, gives each background event the parameters of a random real signal point. §5 · lines 314–404
  4. Weights. compute_event_weights(): background gets its cross-section weight; signal gets a constant weight such that Σwsig = Σwbkg. line 375
  5. Features. feature_list() keeps the variables present in both signal and background (warning about missing ones) and puts the conditional parameters last. line 407
  6. Split. split_train_test() does the 70/30 split, sends the --holdout points to test and caps training at --train-max-events. §6 · lines 418–452
  7. Loop over bins. For each lxy bin, train_one_bin() calls train_bdt() or train_pnn(), saves the model and writes importances, curves and manifest. §9 · lines 752–830

Sections §7a (BDT), §7b (PNN) and §8 (plots and manifest) hold the functions that loop calls.

PNN details

train_pnn() (line 600) does, in order:

  1. Internal validation. Takes 20 % of the training rows (max 1 M) for early stopping. The real test set is never touched.
  2. Standardisation. Per-variable mean and std fitted on train only; NaN and inf are set to 0 (the mean).
  3. Balanced sampling. Each epoch draws 500 k events with probability proportional to the weight, normalised so signal and background each sum to 0.5. Every batch is then ~50/50 and the loss needs no weights.
  4. Background parameters. If conditional, the background parameters are re-drawn from the real signal points in every batch, so the network cannot learn to separate on the parameters.
  5. Network. [Linear → Dropout → ELU] × n_layers → Linear, producing a logit. Adam with BCEWithLogitsLoss.
  6. Learning rate and stopping. The lr is multiplied by 0.9 whenever the training loss goes up. Training stops after patience epochs without a relative validation improvement above 0.01 %, never before epoch 20. The best state is restored.
  7. Importance. Permutation importance on up to 200 k validation events: drop in weighted AUC when each column is shuffled.

One line is printed per epoch during training:

    epoch  12  train loss 0.31842  val loss 0.32107  lr 9.00e-04

Next: evaluation

evaluate_workingpoint.py rebuilds the same split and evaluates on the test set without retraining. The data options must match the training run; --model-dir saves you from reconstructing the directory name:

python3 BDT/evaluate_workingpoint.py --scenario A --sig-dir tuples_DQCD_ScenarioA \
    --model-dir BDT/significance_plots_priv/ScenarioA

If you trained with --conditional, --cond-var, --holdout, --require-l1, --mass-point, --mratio-grid or --do-random-splitting, repeat them exactly.

Caveats

Evaluation only reads BDTs. evaluate_workingpoint.py looks for bdt_lxy_<bin>.json and does not yet load pnn_lxy_<bin>.pt. To evaluate the PNN it needs adapting with PNNClassifier.load(), whose predict_proba has the same shape as XGBoost's.
The BDT overwrites. --model bdt writes to the same directory as workingpoint.py (no _PNN suffix). Use --out-name to keep a previous training.
  • In the conditional BDT the background parameters are assigned once at load time; in the PNN they are re-drawn every batch.
  • With --do-random-splitting, evtn is not read and the split depends on the order of the loaded events.
  • The seed is fixed (42), so two identical runs give the same split and, on CPU, the same model.
